## Context

Plexus is a FalkorDB-based shared memory system for AI agents, built for the
FalkorDB Graph Hacks hackathon (Track 2), repo: this worktree, branch
`feature/neuro-memory-research`, checked out from `main` at commit f96df06.
Read `docs/PLAN.md`, `DECISIONS.md`, `BASELINE.md`, and
`reference/FALKORDB_REFERENCE.md` first, plus any `PLEXUS_REPORT*` doc, to
understand the current architecture and what has already been built/tested
(facts with subject/predicate/value, provenance via sources, decisions,
episodes, task DAGs, pin/unpin, review dates, quarantine/verify-fact,
memory_sweep with dormant/active states, memory_strength scoring,
fact_history/as_of temporal queries, who_knew/why_recalled explainability).

Known, user-stated ground truth to NOT re-litigate: in prior benchmarking
(see PLEXUS_REPORT / P9 section), Plexus's graph-based recall TIED with a
plain SQL baseline on the retrieval-quality benchmarks run so far. The graph
clearly wins on provenance/explainability (who-asserted-what-when) but has
NOT yet demonstrated a retrieval-quality edge. The user wants this
specifically improved, and is independently interested in making the system
actually model human-like forgetting (not just a fixed memory_sweep
dormant/active toggle) because biological forgetting is theorized to improve
signal-to-noise in recall, not just save space.

## Phase 1 — Parallel research survey (delegate_task, Sonnet 5.5 subagents)

Spawn 5-6 subagents in parallel, each researching ONE neuroscience/cognitive
memory mechanism and producing a short cited writeup (include real sources:
papers, textbook chapters, review articles — use web_search/web_extract) that
ends with a CONCRETE mapping to a Plexus feature or schema/algorithm change.
Suggested split (adjust if you find a better division):

1. Forgetting curves & decay (Ebbinghaus, power-law retention, ACT-R base-level
   activation decay) — map to a numeric decay/scoring function for
   memory_strength and fact ranking.
2. Memory consolidation & systems consolidation (hippocampal replay,
   sharp-wave ripples, synaptic vs. systems consolidation, sleep's role) — map
   to a background "consolidation pass" that promotes/demotes facts, maybe
   literal analogue to memory_sweep but driven by access patterns + replay
   instead of a fixed schedule.
3. Spacing effect & testing effect (distributed practice, retrieval practice
   strengthens memory) — map to: does recall/verification of a fact via
   verify_fact or who_knew/as_of count as a "retrieval event" that should
   strengthen and reset decay on that fact, spaced-repetition-style.
4. Interference theory & pattern separation/completion (proactive/retroactive
   interference, dentate gyrus pattern separation, hippocampal pattern
   completion, catastrophic interference in neural nets) — map to conflict
   detection between facts, how Plexus should resolve/merge near-duplicate or
   contradicting facts instead of just quarantining.
5. Salience/emotional tagging & amygdala-modulated consolidation (emotionally
   or task-critically salient events are remembered better and longer) — map
   to using pin_fact/importance signals (e.g., how often a fact gates a
   decision, verify_artifact calls, task completions) as a salience signal
   that slows decay, instead of pinning being all-or-nothing.
6. (if a 6th is useful) Reconsolidation & memory updating on retrieval
   (recalled memories become labile and are re-stored, which is how
   corrections/updates naturally happen) — map to how fact_history/verify_fact
   should actively rewrite confidence/strength on each recall, not just log
   history passively.

Each subagent should explicitly address: (a) the real neuroscience mechanism
and its best-supported model/parameters, (b) why it's relevant to recall
QUALITY specifically (not just storage cost) for an agent memory system,
(c) a concrete, falsifiable design: what Cypher/schema/scoring change would
implement it in Plexus, and how it would be benchmarked against the existing
SQL-tie baseline. Each subagent should write its findings to
`docs/research/neuro-memory/<topic-slug>.md` in this worktree.
