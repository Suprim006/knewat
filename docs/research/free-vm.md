# $0 hosting for the FalkorDB + FastAPI demo (judging window: ~Oct 18 – late Nov 2026)

Researched 2026-10-14. **[inf]** = my inference, not stated by a source. **[unk]** = could not find a statement. "Secondary" = third-party page. Complements [hosting.md](hosting.md) (Railway Hobby $5/mo etc.); this file only covers $0 routes. Prices/limits are volatile: re-check on the day you sign up.

## 0. Bottom line (Nepal, no reliable international card assumed)

| Rank | Option | Why | Needs card? |
|---|---|---|---|
| 1 | **Render Free**, ONE Docker web service running FalkorDB + FastAPI, reseed on boot, 5-min uptime pinger | Only candidate that is $0, has a real Docker runtime, and appears to work with no payment method; deployable in an evening. Cost: sleeps/cold start, 512 MB ceiling | Apparently no (see §2.1) |
| 2 | **AWS Free plan EC2** (t4g.small / t3.small, 6 months) – or **Azure for Students** VM if you're a student | Always-on VM with disk, no sleeping, 6-month window covers the judging; both say a card is not required for most/student sign-ups | "Most new customers: no" / Azure Students: no |
| 3 | **Oracle Always Free Ampere A1** | Best resources (2 OCPU / 12 GB), free forever; but card check is strict, capacity errors and idle reclamation are real | **Yes** (no prepaid/virtual cards) |

Not recommended as $0: Hugging Face Docker Spaces (now needs PRO, $9/mo), Fly.io, Railway Free ($1/mo credit), Koyeb Free (0.1 vCPU, card), GCP e2-micro (1 GB, card). Details below. If a $5–9/mo spend is acceptable, [hosting.md](hosting.md)'s Railway Hobby remains the lowest-effort *reliable* path.

## 1. Nepal / card reality check
- Oracle: "We do not accept debit cards with a PIN or virtual, single-use, or prepaid cards" ([Oracle FAQ](https://www.oracle.com/cloud/free/faq/)). Nepali USD cards are normally prepaid, limited to USD 500/yr per person ([KharchaPatra, secondary](https://kharchapatra.com/blog/pay-netflix-aws-chatgpt-from-nepal)); one Nepali user reports a $1.1 verification charge followed by account rejection with a Global IME dollar card ([r/technepal, anecdote](https://www.reddit.com/r/technepal/comments/1rfbp5r/oracle_cloud_charged_1_for_verification_but/)). Expect Oracle to be a coin-flip **[inf]**.
- Google Cloud: "Prepaid cards aren't accepted" and debit cards that require two-factor authentication aren't accepted ([GCP payment methods](https://cloud.google.com/billing/docs/how-to/payment-methods)).
- Azure free account: needs phone + credit or non-prepaid debit card, and "If your country is not listed, the offer is not available in your region" ([Azure free account](https://azure.microsoft.com/en-us/pricing/purchase-options/azure-account?icid=azurefreeaccount)); Nepal listing **[unk]**.

## 2. Options in detail

### 2.1 Render Free (single container) — rank 1
- **Cost/limits:** $0; Free web service 512 MB RAM, "Less than 1 CPU" ([pricing](https://render.com/pricing)); 750 free instance hours per workspace per month; one service running 24/7 uses ~744 h (31 days) so it fits **[inf]** ([Render Free](https://render.com/docs/free)). If hours run out and no payment method was added, Render suspends free services for the rest of the month (same page).
- **Sleep:** spins down after 15 min with no inbound traffic (HTTP or WebSocket); wakes on next request in "about one minute" with a loading page ([Render Free](https://render.com/docs/free)).
- **Persistence:** none — filesystem lost on redeploy/restart/spin-down; persistent disks are paid-only; free Postgres expires after 30 days (same page). => reseed on every boot (§3).
- **Runs FalkorDB?** Pricing page lists "Custom Docker containers" ([pricing](https://render.com/pricing)) so a Dockerfile starting `redis-server --loadmodule falkordb.so` plus uvicorn is plausible **[inf]**; I did not find a doc that forbids extra processes, but I did not test it. Only the web port is public; Redis stays on localhost **[inf]**.
- **HTTPS:** yes ("Web services with HTTP/2 and full TLS", [pricing](https://render.com/pricing)).
- **Card:** the free-tier page describes behaviour "If you haven't added a payment method" ([Render Free](https://render.com/docs/free)), implying free services work without one **[inf]**; confirm at signup.
- **Effort:** low (Dockerfile + repo + env secrets). **Main risk:** 512 MB shared by Redis+module+Python+LLM client — measure with `docker stats` locally first **[inf]**; cold start (~1 min + reseed) on the first judge visit if the pinger fails.

### 2.2 AWS Free plan (post-July-2025 credit model) — rank 2
- **Cost/duration:** new accounts get $100 credits on sign-up + up to $100 more for activities; "The account closes on its own 6 months after you open it or when your credits run out, whichever comes first" ([AWS Free Tier](https://aws.amazon.com/free/)). Plan expires at the earlier of 6 months or credit exhaustion; cannot be extended; after expiry AWS suspends the account, keeps data 90 days, and you must upgrade to a Paid plan to restore ([Free Tier FAQ](https://aws.amazon.com/free/faqs/)). For an account opened ~Oct 15, 2026 that means ~mid-April 2027 **[inf]** — covers the judging window.
- **Instances:** accounts created on/after July 15, 2025 can use t3.micro, t3.small, t4g.micro, t4g.small, c7i-flex.large, m7i-flex.large ([EC2 Free Tier doc](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-free-tier-usage.md)). t4g.small/t3.small = 2 GB RAM **[inf]** (not on the pages read); t4g is Arm and FalkorDB publishes arm64 images ([hosting.md](hosting.md)).
- **Card:** "A payment method isn't required to sign up for most new customers. In some cases, we may request additional information, such as a payment method" ([FAQ](https://aws.amazon.com/free/faqs/)). Nepal-specific outcome **[unk]**.
- **Persistence/sleep:** EBS root volume persists; never sleeps; no idle rule found. **Credits burn** on EC2 + public IPv4 + EBS **[inf]**; set a billing alert. If credits run out the plan ends (above).
- **HTTPS:** none built in; run Caddy/nginx + a hostname (free DNS service or Cloudflare Tunnel) **[inf]**; this is the extra effort. **Effort:** medium. **Main risk:** signup/verification failing from Nepal; credit exhaustion if you pick a large instance.

### 2.3 Azure — free account vs Azure for Students — rank 2 (alt)
- **Free account:** $200 credit for up to 30 days; "12 months" free "750 hours each of B1s, B2pts v2 (Arm-based), and B2ats v2 (AMD-based) burstable VMs"; to keep 12-month services you must move to pay-as-you-go within 30 days ([Azure free account](https://azure.microsoft.com/en-us/pricing/purchase-options/azure-account?icid=azurefreeaccount), [free services](https://azure.microsoft.com/en-us/pricing/free-services/)). Card required (above). B2pts_v2 and B2ats_v2 = 2 vCPU, 1 GiB ([Bpsv2](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/general-purpose/bpsv2-series), [Basv2](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/general-purpose/basv2-series)); base CPU 20%. 1 GiB is tight for Redis+Python **[inf]**; add swap.
- **Azure for Students:** "No credit card required", academic email only, full-time university students, $100 credit "within 12 months", renewable annually while a student ([Azure for Students](https://azure.microsoft.com/en-us/free/students/)). Whether the 12-month free VM hours also apply to student accounts: **[unk]** (page says "Free monthly amounts of 20+ popular services for 12 months"); the $100 credit should cover one small VM for 6 weeks **[inf]**. Nepali university eligibility **[unk]** — try with the .edu.np address.
- **Persistence/sleep:** normal VM, none. **HTTPS:** DIY (Caddy). **Effort:** medium. **Risk:** 1 GiB RAM; eligibility.

### 2.4 Oracle Cloud Always Free — rank 3
- **Free forever** in the *home region* ([Always Free](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)): Ampere A1 = first 1,500 OCPU-h + 9,000 GB-h/month = 2 OCPUs + 12 GB (the older-dated [resource ref, 2025-08-05](https://docs.oracle.com/iaas/Content/FreeTier/resourceref.htm) says 3,000/18,000 = 4 OCPU/24 GB: conflicting pages; plan on 2/12); up to two AMD E2.1.Micro (1/8 OCPU, 1 GB — too small); 200 GB block volume total, 47–50 GB min boot volume.
- **Home region lock:** compute must be created in the home region; the home region "can't [be changed] after your tenancy is provisioned" ([regions](https://docs.oracle.com/en-us/iaas/Content/Identity/regions/managingregions.htm)). Mumbai (ap-mumbai-1) and Hyderabad (ap-hyderabad-1) exist ([region list](https://docs.oracle.com/en-us/iaas/Content/General/Concepts/regions.htm)); closest to Nepal **[inf]**. Pick the region once, carefully; popular regions may be short of capacity **[inf]**.
- **Out of capacity:** "out of host capacity" = temporary lack of Always Free shapes; try another availability domain, wait, or upgrade to Pay-As-You-Go (Always Free stays free) ([docs](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm), [FAQ](https://www.oracle.com/cloud/free/faq/)).
- **Idle reclamation:** Oracle may reclaim an instance if over 7 days CPU 95th percentile < 20%, network < 20% and (A1 only) memory < 20% — a quiet demo VM matches ([docs](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)). Also accounts idle ≥30 days "may be deemed abandoned" ([FAQ](https://www.oracle.com/cloud/free/faq/)). Whether PAYG upgrade exempts you from reclamation: **[unk]**.
- **Card:** required, with a temporary authorization hold; no prepaid/virtual/PIN-debit ([FAQ](https://www.oracle.com/cloud/free/faq/)). **HTTPS:** DIY. **Effort:** high. **Main risk:** signup rejection from Nepal; capacity; reclamation.

### 2.5 Google Cloud — e2-micro VM and Cloud Run
- **e2-micro Always Free:** 1 non-preemptible e2-micro/month in us-west1, us-central1 or us-east1, 30 GB-months standard disk, 1 GB NA egress ([GCP free features](https://cloud.google.com/free/docs/free-cloud-features)); e2-micro = 2 shared vCPUs, 0.25 vCPU sustained, 1 GB; bursts ~30 s ([machine types](https://cloud.google.com/compute/docs/general-purpose-machines)). Sign-up requires a credit card/payment method and sometimes bank-account verification ([same page](https://cloud.google.com/free/docs/free-cloud-features)); $300/90-day trial. US-only regions => latency from Nepal **[inf]**. 1 GB + 0.25 vCPU is the weakest VM here. Not recommended.
- **Cloud Run (scale-to-zero container, in-container FalkorDB + reseed):** free tier (request-based billing) = 180,000 vCPU-s, 360,000 GiB-s, 2 M requests/month; instance-based = 240,000 vCPU-s / 450,000 GiB-s ([pricing](https://cloud.google.com/run/pricing)). Idle instances live ≤15 min unless min-instances is set ([billing settings](https://cloud.google.com/run/docs/configuring/billing-settings)). `min-instances=1` 24/7 would exceed the free tier (6 weeks ≈ 3.6 M s vs 240 k vCPU-s) **[inf]** — so run scale-to-zero, reseed on every cold start; cold start = container start + Redis + seed. Mumbai (asia-south1) is a listed region ([pricing](https://cloud.google.com/run/pricing)). HTTPS built in **[inf]**. **Needs a GCP billing account => card** (prepaid refused). Best technical $0 serverless fit *if* you hold a normal credit card; effort low–medium.

## 3. Reseed-on-boot design (inference; for Render, Cloud Run, Koyeb, HF, or any VM that may be rebuilt)
1. Bake the seed data (CSV/JSON/Cypher) and the seed script into the image; never fetch it at runtime. [inf]
2. One entrypoint: start `redis-server` with the FalkorDB module, persistence off (`--save "" --appendonly no`) and a `maxmemory` below the platform limit; wait for `PING`; run the seed if the graph is missing (`GRAPH.LIST`), otherwise skip; then exec uvicorn. [inf]
3. Make seeding idempotent (drop + rebuild, or `MERGE`); the whole graph is <200 MB so seeding should take seconds. [inf] Time it locally.
4. `/health` returns 503 until the seed finishes; the web UI shows a "waking up…" state instead of an error. [inf]
5. LLM key in platform secrets; per-IP rate limit and a spend cap so judge traffic can't drain it. [inf]
6. VMs: mount a volume at `/var/lib/falkordb/data` + `restart: unless-stopped` ([persistence docs](https://docs.falkordb.com/operations/durability/persistence)), but keep the reseed step as a safety net. [inf]

## 4. Keep-alive & monitoring
- **UptimeRobot Free:** $0, 50 monitors, 5-minute interval, "No credit card required!" ([pricing](https://uptimerobot.com/pricing/)). A 5-min HTTP check to `/health` stays inside Render's 15-min idle window **[inf]**; Koyeb's 1-h window is also covered.
- **ToS flags:** Render's free page frames spin-down as a limitation and I found no explicit rule about pings either way [unk] — it also burns instance hours (one service ≈ 744 h < 750). Koyeb says scale-to-zero "cannot be disabled" but states nothing about pings [unk]. Treat pinging as grey-area: keep it to a single light `/health` request every 5 min, no load generation, remove it after judging. Oracle: don't fake CPU load to evade the reclamation rule — that circumvents its policy **[inf]**; instead log in monthly and size the VM so real use is higher. Cloud Run: do **not** ping — it would keep an instance billed; accept the cold start.
- **Insurance:** set an email alert on 2 failed checks; ship README + demo video too ([hosting.md](hosting.md) says the hackathon accepts them in lieu of a live deployment). Before deploy day, measure RAM with `docker stats` (target <~350 MB steady) **[inf]**.
