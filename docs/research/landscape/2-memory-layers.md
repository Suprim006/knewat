## 2. Per-system notes

**Mem0.** USP: simplest API; after the April 2026 rewrite it claims LoCoMo 92.5, LongMemEval 94.4, BEAM-1M 64.1 on the managed platform, which "includes proprietary optimizations not available in the open-source SDK" ([README](https://github.com/mem0ai/mem0)). Its paper reported 26% relative LLM-judge gain over OpenAI memory, 91% lower p95 latency and >90% token savings versus full context ([paper](https://arxiv.org/abs/2504.19413)). Limits: a 32-day production audit found 97.8% of 10,134 entries were junk ([#4573](https://github.com/mem0ai/mem0/issues/4573), closed; one deployment, a Qdrant backend and two extraction models). The dedup race ([#6515](https://github.com/mem0ai/mem0/issues/6515)), a related entity-store race (#6243) and Qdrant HNSW corruption under concurrent writes (#4892) are cited in that issue. An ADD-only store has no invalidation, so stale facts need ranking to hide them [inf]. The graph is entity co-occurrence linking, not typed relations ([docs](https://docs.mem0.ai/open-source/features/graph-memory)).

**Zep / Graphiti.** USP: bi-temporal fact edges; the paper reports DMR 94.8% vs MemGPT 93.4%, and LongMemEval accuracy up to +18.5% with ~90% lower latency than full context ([paper](https://arxiv.org/html/2501.13956v1)). The paper itself says DMR conversations (60 messages) fit in context. Graphiti is Apache-2.0 and supports FalkorDB 1.1.2 ([README](https://github.com/getzep/graphiti)). Limits: expensive ingestion, so users set `SEMAPHORE_LIMIT=1` to avoid 429s and get ~36 s/record ([#1262](https://github.com/getzep/graphiti/issues/1262)). Invalidation is LLM-judged and inconsistent ([#1841](https://github.com/getzep/graphiti/issues/1841): "released from project" does not invalidate "assigned"). FalkorDB driver bug: `retrieve_episodes` can return episodes after `reference_time` ([#1625](https://github.com/getzep/graphiti/issues/1625)). Self-hosting is Graphiti only; Zep CE is deprecated ([FAQ](https://help.getzep.com/faq)).

**Letta.** USP: agent-managed memory (core blocks, recall, archival) from MemGPT. Shared blocks give instant cross-agent visibility ([docs](https://docs.letta.com/guides/agents/multi-agent-shared-memory)). Notably, those docs now say "We do not recommend building on memory blocks anymore" and point to shared memory repositories / MemFS (git-backed) for new work. Sleep-time agents rewrite memory asynchronously on a shared block. Letta reported 74.0% on LoCoMo with gpt-4o-mini by storing histories in plain files ([blog](https://letta.com/blog/benchmarking-ai-agent-memory)). Limits: blocks are text with no typed relations or temporal validity; no conflict-resolution semantics documented. [inf] A git merge model is the closest thing to a concurrency story.

**Cognee.** USP: graph + vector + relational pipeline (`remember`/`recall`/`improve`), dataset-level ACL with tenants and roles ([docs](https://docs.cognee.ai/core-concepts/multi-user-mode/permissions-system/overview)). Provenance ledger and conflict review exist but are off by default ([docs](https://docs.cognee.ai/python-api/remember)). Vendor docs cite "up to 92.5% accuracy" without stating the benchmark in the snippet I read, so I treat it as unverified. Already has a FalkorDB community adapter ([docs](https://docs.falkordb.com/agentic-memory/cognee)), so it is a competitor and a possible integration at once [inf]. 754 open issues ([repo](https://github.com/topoteretes/cognee)).

**LangMem + LangGraph Store.** USP: the only entry here with procedural memory as first-class (prompt optimizer updates rules) and an explicit hot-path vs background choice ([conceptual guide](https://github.com/langchain-ai/langmem/blob/main/docs/docs/concepts/conceptual_guide.md)). Store is a namespaced KV API, so no relations. In Mem0's paper LangMem was a baseline; Mem0 used `InMemoryStore` in its harness ([code](https://github.com/mem0ai/mem0/blob/2274b5ac/evaluation/src/langmem.py)), which is a configuration caveat for any LangMem latency comparison.

**Supermemory.** USP: versioned facts with `updates`/`extends`/`derives` edges and `isLatest`, plus connectors and profiles. README says "#1 on LongMemEval, LoCoMo, ConvoMem"; its blog gives 85.4% on LongMemEval ([blog](https://supermemory.ai/blog/best-memory-apis-stateful-ai-agents)). Both are self-reported. Backend not disclosed.

**MemOS.** USP: treats plaintext, activation and parameter memory as one scheduled resource; MemCube holds provenance/versioning ([paper](https://arxiv.org/abs/2507.03724)). Multi-cube sharing is the closest to explicit multi-agent policy in OSS. I found no concurrency spec.

**A-MEM.** USP: Zettelkasten notes plus LLM-created links; old notes can be rewritten ([paper](https://arxiv.org/abs/2502.12110)). Research code, ChromaDB, no multi-user story ([repo](https://github.com/agiresearch/a-mem)).

**Memobase.** Profile-first; buffer then flush ([docs](https://docs.memobase.io/features)). Lossy for episodic detail [inf].

**CrewAI / LlamaIndex / OpenAI Sessions.** CrewAI's hierarchical scopes and read barrier are the best framework-level multi-agent primitives I found; consolidation is LLM-decided ([docs](https://docs.crewai.com/v1.11.0/en/concepts/memory)). LlamaIndex and OpenAI Sessions are history/summary layers, not knowledge stores.

**AgentCore / Memory Bank.** Managed, opaque storage. Memory Bank's per-step revisions are a good audit model ([docs](https://docs.cloud.google.com/gemini-enterprise-agent-platform/scale/memory-bank/generate-memories?authuser=44&hl=en)). AgentCore's `actorId` can be an agent ([docs](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-memory.html)). Cloud lock-in; no graph queries.

## 3. Benchmarks

| Benchmark | Measures | Notes |
|---|---|---|
| [LoCoMo](https://arxiv.org/abs/2402.17753) | QA, summarization, multimodal over ~300-turn, up to 35-session dialogues | Most vendor comparisons use it. Audit: 99 score-corrupting answer-key errors (6.4% of 1,540), ceiling ~93.6% ([audit](https://github.com/dial481/locomo-audit/blob/main/AUDIT_REPORT.md)); judge accepted up to 63% of intentionally wrong answers ([post](https://dev.to/penfieldlabs/we-audited-locomo-64-of-the-answer-key-is-wrong-and-the-judge-accepts-up-to-63-of-intentionally-33lg)). [inf] Mem0's 92.5 is within ~1 point of that ceiling, so score gaps there are mostly noise. |
| [LongMemEval](https://arxiv.org/abs/2410.10813) (ICLR 2025) | 500 questions: extraction, multi-session reasoning, temporal reasoning, knowledge updates, abstention | Commercial assistants and long-context LLMs show a 30% accuracy drop. Critique: the S variant uses ~115K tokens, so it fits long context windows ([post](https://dev.to/penfieldlabs/we-audited-locomo-64-of-the-answer-key-is-wrong-and-the-judge-accepts-up-to-63-of-intentionally-33lg)). |
| [MemoryAgentBench](https://arxiv.org/abs/2507.05257) (ICLR 2026) | Accurate retrieval, test-time learning, long-range understanding, selective forgetting | Current methods fall short of mastering all four. |
| [BEAM](https://arxiv.org/abs/2510.27246) | Up to 10M-token conversations, 2,000 questions | Even 1M-context LLMs struggle as dialogues lengthen. |
| [MemoryArena](https://arxiv.org/abs/2602.16313) (ICML 2026) | Memory used for action across interdependent multi-session tasks | Agents near saturation on LoCoMo "perform poorly" here. |
| [LongMemEval-V2](https://arxiv.org/abs/2605.12493) | Environment experience for web agents: state tracking, workflows, gotchas; up to 115M tokens | Closest to procedural memory. Work in progress. |
| [Collaborative Memory](https://arxiv.org/abs/2505.18279) | A framework, not a benchmark: private vs shared tiers, immutable provenance, bipartite-graph access control | Shows the multi-user design space. No scores found. |

**The Mem0 / Zep / Letta dispute (both sides).**
- Mem0's paper ranked itself above Zep on LoCoMo ([paper](https://arxiv.org/abs/2504.19413)). Zep says Mem0 misconfigured Zep (e.g., sequential searches) and that a correct run scores 75.14% ± 0.17, about 10% above Mem0's best ([Zep blog](https://www.getzep.com/blog/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/)).
- Zep's first rebuttal claimed 84%. Mem0's CTO replied that it counted adversarial-category correct answers in the numerator but not the denominator and re-ran it to 58.44% ([zep-papers#5](https://github.com/getzep/zep-papers/issues/5)). Zep then issued the corrected 75.14% and later claims 80% at <200 ms (same blog; self-reported).
- Letta says it could not find a way to backfill LoCoMo into MemGPT, that Mem0 did not respond to requests for clarification, and that a plain filesystem agent reached 74.0% ([Letta blog](https://letta.com/blog/benchmarking-ai-agent-memory)).
- Independent audits say these numbers are not comparable across vendors: different prompts, judges, categories ([audit](https://github.com/dial481/locomo-audit)). I could not find a neutral re-run of all vendors on one harness.

**What the benchmarks do NOT measure** [inf, from the scopes above]: (a) concurrent writers or race outcomes; (b) multi-agent handoffs and shared state (Collaborative Memory has none); (c) per-tenant isolation or leakage; (d) write-side cost and ingest throughput; (e) provenance or explanation quality; (f) procedural-memory improvement over time (only LME-V2 and MemoryArena come close); (g) invalidation correctness (MemoryAgentBench's forgetting is the nearest).

## 4. White space for a FalkorDB Track-02 project (all [inf])

1. **Concurrent multi-agent writes with a real consistency story.** Gap: Mem0 has open dedup races ([#6515](https://github.com/mem0ai/mem0/issues/6515)); Letta shares blocks with no documented merge semantics; Graphiti MCP serializes per group in app code. FalkorDB runs one atomic write at a time per graph with consistent-snapshot parallel reads ([docs](https://docs.falkordb.com/design/concurrency)), and `MERGE` can fold check-and-insert into one query. Demo: N agents writing the same fact, zero duplicates.
2. **Server-side fact invalidation.** Gap: Graphiti's invalidation is LLM-judged and inconsistent ([#1841](https://github.com/getzep/graphiti/issues/1841)); Mem0 dropped updates. One Cypher query can close the old edge (`SET invalid_at`) and create the new one atomically.
3. **Per-tenant and per-agent graphs.** Gap: Mem0 and CrewAI isolate by ID or scope inside one store; Cognee uses per-dataset stores. FalkorDB manages thousands of graphs per instance ([blog](https://falkordb.com/blog/scale-out)), so private-per-agent plus shared-team graph is a physical isolation boundary, not a filter.
4. **Handoff as a first-class graph object.** Gap: no system models Task/Handoff/Decision nodes. Letta, CrewAI and Collaborative Memory share memory but not a work state. Handoff nodes linked to the memories, evidence and agents involved make "why did agent B do this" a traversal.
5. **Procedural memory as a graph.** Gap: only LangMem (prompt rules) and LME-V2 (workflows) address it. Skills/playbooks as nodes with `SUCCEEDED_ON`/`FAILED_ON` episode edges, ranked by success counts, enable "which procedure works for this task".
6. **Provenance as a queryable path.** Gap: Cognee's ledger is off by default; Mem0 has no provenance; Collaborative Memory's immutable provenance is paper-only. Memory → episode → source-turn edges answer "why does the agent believe this?" in one Cypher path.
7. **Hybrid retrieval in one query.** Gap: Mem0 fuses semantic, BM25 and entity matching in its own pipeline. FalkorDB has vector (HNSW) and full-text indexes ([docs](https://docs.falkordb.com/cypher/indexing/vector-index.html)) in the same engine as graph expansion, so vector seed → N-hop expansion → time filter is one query.
8. **Graph algorithms for consolidation and forgetting.** Gap: forgetting is LLM- or threshold-based (CrewAI 0.85, Supermemory "automatic forgetting"). FalkorDB ships centrality and path algorithms ([docs](https://docs.falkordb.com/algorithms/index.md)); PageRank/community detection could drive salience-based decay without LLM calls.
9. **A multi-agent memory benchmark.** Gap: none of the benchmarks above covers concurrency or handoff. Shipping a small harness (N writers, conflicting facts, tenant-leak probes, handoff accuracy), run against Mem0, Graphiti and the FalkorDB build, would be a differentiated deliverable. Caveat: build it honestly, since vendors have been burned on harness fairness.
10. **Low ingest cost.** Gap: Graphiti needs ~6-10 LLM calls per episode. Cheap deterministic write paths (store raw episode edges first, extract asynchronously) bring write cost down, with sleep-time-style consolidation as the Letta idea on a graph.
11. **Bi-temporal queries as agent tools.** Gap: Graphiti stores both timelines, but few demos query "what did agent A believe on Tuesday vs what was true". Cypher time-range filters on the same graph make "belief at time T" demos cheap.
12. **Inspectability UI.** Gap: MemOS and Supermemory ship graph views, but most others don't. A live view of memory graph, handoffs and per-tenant graphs would make the Track-02 story visible to judges.

**Positioning caveat.** Graphiti and Cognee already run on FalkorDB, so a winning project should show something they don't: points 1, 3, 4, 5 and 9 are the least covered.
