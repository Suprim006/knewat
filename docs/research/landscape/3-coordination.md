# Landscape 3 — Multi-agent coordination today, and where a shared graph fits

Track 02 "Agent Memory and Coordination" (Graph Hacks / FalkorDB). Researched 2026-10-14. Each factual claim links to a page I opened. `[inf]` = my inference. `[first-hand]` = observed by the orchestrating Claude Code today. Some 2026 arXiv items were read only as abstracts or search excerpts; flagged below. "Claude Code delegate_task + kanban" in the brief is the **Hermes** feature set; Claude Code's own equivalents are subagents and agent teams. Both are covered.

## 2. Per framework: USP, strengths, documented limits

**LangGraph.** USP: a checkpointed graph. [Checkpointers give thread-scoped time travel and fault tolerance; Stores give cross-thread memory](https://docs.langchain.com/oss/python/langgraph/persistence). Strengths: [pending writes from successful nodes survive a failed super-step](https://docs.langchain.com/oss/python/langgraph/checkpointers); handoffs via [`Command`](https://docs.langchain.com/oss/python/langgraph/graph-api) and a [swarm that remembers the last active agent](https://github.com/langchain-ai/langgraph-swarm-py). Limits: unreduced parallel writes [raise an error](https://docs.langchain.com/oss/python/langgraph/errors/INVALID_CONCURRENT_GRAPH_UPDATE); subgraph updates may not reach the parent because [each has its own checkpoint namespace](https://docs.langchain.com/oss/python/langgraph/persistence); Store prefix search [silently truncates past `limit`](https://docs.langchain.com/oss/python/langgraph/stores); the supervisor library now [recommends the tool-based pattern instead](https://github.com/langchain-ai/langgraph-supervisor-py). [inf] State is a per-thread blob; "who decided X" needs custom code.

**OpenAI Agents SDK.** USP: handoffs are tools, e.g. [`transfer_to_refund_agent`](https://openai.github.io/openai-agents-python/handoffs/). Strengths: [multiple session backends](https://openai.github.io/openai-agents-python/sessions/); tracing wraps [handoffs in spans](https://openai.github.io/openai-agents-python/tracing/). Limits: the receiver [still sees the history unless filtered](https://openai.github.io/openai-agents-python/handoffs/); context is [not sent to the LLM, and nested `as_tool()` runs share app state by default](https://openai.github.io/openai-agents-python/context/). [inf] Shared world state is a Python object: no schema, versions or claims.

**CrewAI.** USP: role crews with [sequential or hierarchical processes](https://docs.crewai.com/en/concepts/processes.md) and [delegation tools](https://docs.crewai.com/en/concepts/collaboration.md). Strengths: Memory with [private scopes and read-only slices](https://docs.crewai.com/en/concepts/memory.md), per-customer isolation as a documented pattern, Flow state via [`@persist`](https://docs.crewai.com/en/concepts/flows.md). Limits: similar records trigger an [LLM keep/update/delete/insert decision](https://docs.crewai.com/en/concepts/memory.md), so merge is model-judged [inf: non-deterministic]; default storage is [local LanceDB](https://docs.crewai.com/en/concepts/memory.md).

**AutoGen.** USP: conversation patterns, [broadcast with LLM speaker selection](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/selector-group-chat.html) and [swarm handoffs over a shared message context](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/swarm.html). Strength: [state is a serializable dict](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/state.html). Limit: [maintenance mode; Microsoft Agent Framework is the successor](https://github.com/microsoft/autogen). [inf] Everyone reads everything, so cost and noise grow with team size.

**AG2.** USP: [group chat manager broadcasting to all](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/groupchat/groupchat/) plus [Context Variables that persist across agent transitions](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/context-variables/). Limit: I found no documented concurrent-writer semantics. [inf] Conversation-scoped, not a cross-session store.

**Google ADK.** USP: a coordinator whose `sub_agents` become [auto-injected delegation tools](https://google.github.io/adk-docs/workflows/collaboration/). Strengths: [`app:`/`user:`/`temp:` state scopes](https://google.github.io/adk-docs/sessions/state/); [session state separate from a long-term MemoryService](https://google.github.io/adk-docs/sessions/); [A2A support](https://google.github.io/adk-docs/a2a/). Limits: `ParallelAgent` children are independent; sharing needs [locks to avoid race conditions, or an external DB](https://google.github.io/adk-docs/agents/workflow-agents/parallel-agents/); [task mode is disabled in graph workflows in Python v2.0.0](https://google.github.io/adk-docs/workflows/collaboration/).

**A2A.** USP: interop between [independent, potentially opaque agent systems](https://a2a-protocol.org/latest/specification/); agents [can't see each other's internals](https://a2a-protocol.org/latest/topics/what-is-a2a/). Strengths: [`contextId` groups tasks](https://a2a-protocol.org/latest/topics/life-of-a-task/); a [`tenant` field](https://a2a-protocol.org/latest/topics/multi-tenancy/). Limits: no shared memory by design; artifact version history is [left to the client, not in the spec](https://a2a-protocol.org/latest/topics/life-of-a-task/). [inf] Good for crossing org boundaries, not for agreeing on facts.

**MCP.** USP: standard tool/context plug; A2A calls it [complementary](https://a2a-protocol.org/latest/topics/a2a-and-mcp/). What it does NOT do: the protocol is [stateless, each request carrying version and capabilities](https://modelcontextprotocol.io/docs/learn/architecture); Tasks are [experimental in the 2025-11-25 spec](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/tasks) and only bound to an authorization context where one exists. [inf] No claim, lease, conflict or provenance primitive; a shared-state MCP server must supply them.

**MetaGPT.** USP: [`Code = SOP(Team)`](https://raw.githubusercontent.com/FoundationAgents/MetaGPT/main/README.md); agents [publish structured messages to a shared pool and subscribe by profile](https://arxiv.org/html/2308.00352). Strength: [executable feedback](https://arxiv.org/html/2308.00352); MAST finds [explicit verifiers (MetaGPT, ChatDev) correlate with fewer failures](https://arxiv.org/html/2503.13657v3). [inf] The pool is an append-only broadcast log with no described versioning or conflict handling.

**CAMEL.** [Role-playing paper](https://arxiv.org/abs/2303.17760); [Workforce](https://docs.camel-ai.org/key_modules/workforce) is a central orchestrator over the task lifecycle. I did not verify its memory, concurrency or tenancy.

**Claude Code subagents and teams.** Subagents have [their own context and system prompt](https://code.claude.com/docs/en/sub-agents) and return results to the caller, with optional [user/project/local memory dirs](https://code.claude.com/docs/en/sub-agents). [Agent teams](https://code.claude.com/docs/en/agent-teams) (experimental, off by default) add a task list, mailbox JSON files and [file-locked claiming](https://code.claude.com/docs/en/agent-teams). Documented [limits](https://code.claude.com/docs/en/agent-teams#limitations): no resume for in-process teammates, task status can lag and block dependents, one team per session, no nesting, fixed lead. Overlap is handled by advice: [two teammates editing one file overwrite each other](https://code.claude.com/docs/en/agent-teams).

**Hermes `delegate_task`.** [Isolated child context; only the final summary reaches the parent](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation); 10 concurrent by default; nested depth [multiplies to 27 leaf agents](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation). Hermes's own comparison: the audit trail is [lost on context compression](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban).

**Hermes Kanban.** USP: [every handoff is a row anyone can read and write](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban). Strengths: dispatcher [atomically claims, reclaims stale/crashed workers, WAL SQLite](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban); a guard stops a [second session closing a live worker's run](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban); event log, runs, comments, parent results with decision metadata. Limit: [deliberately single-host](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban). [inf] It models tasks, not facts; conflicting claims about the world are reconciled by comments or an arbiter skill.

**Blackboard.** Three parts: [blackboard, knowledge sources, control component](https://en.wikipedia.org/wiki/Blackboard_(design_pattern)); in Hearsay-II, sources are [independent, anonymous and react to blackboard changes](https://www.ijcai.org/Proceedings/77-2/Papers/055.pdf). LLM revivals: [request/volunteer blackboard, 13–57% relative gains](https://arxiv.org/html/2510.01285v2); [LbMAS with conflict-resolver and cleaner agents](https://arxiv.org/html/2507.01701v1). Practitioner caveat: [termination and quiescence are yours to build](https://tacoda.dev/iii-blackboard). [inf] An architecture, not a product; the open question is the substrate (query, versioning, isolation, provenance).

## 3. Failure modes from the literature

- **MAST** ([Cemri et al.](https://arxiv.org/abs/2503.13657)): 1600+ traces, 7 frameworks, 14 modes in 3 categories. Shares per the [v3 text](https://arxiv.org/html/2503.13657v3): step repetition 15.7%, reasoning–action mismatch 13.2%, missing completion recognition 12.4%, ignoring task requirements 11.8%, wrong verification 9.1%, no/partial verification 8.2%, task derailment 7.4%, proceeding on wrong assumptions 6.8%, context loss 2.8%, ignoring peers 1.9%, withholding information 0.85%. Their withholding example: [an agent never passes an API requirement to its supervisor, who never asks](https://arxiv.org/html/2503.13657v3). The authors argue for [structural redesign over prompt fixes](https://arxiv.org/html/2503.13657v3).
- **Context engineering.** Cognition: [share full traces; actions carry implicit decisions that conflict across parallel agents](https://cognition.com/blog/dont-build-multi-agents). Their follow-up: multi-agent works when [writes stay single-threaded and extra agents add intelligence, not actions](https://cognition.com/blog/multi-agents-working). Anthropic's [research system](https://www.anthropic.com/engineering/multi-agent-research-system): +90.2% over single-agent on breadth-first research at ~15× chat tokens; early failures were duplicated work and vague delegation; synchronous subagents block steering, while async adds "state consistency and error propagation" problems.
- **Memory consistency.** A [2026 position paper](https://arxiv.org/abs/2603.10062) calls it the most pressing open problem and says consistency [has not been formally defined and no framework detects violations](https://arxiv.org/html/2603.10062). Shared memory risks [overwrites, stale reads and inconsistent fact versions](https://arxiv.org/html/2603.10062).
- **Poisoning / contamination** (abstracts and excerpts only): [MAPLE-Guard](https://arxiv.org/html/2608.00426v1), one poisoned write promoted into shared memory contaminates agents that never saw the attack; gating write/retrieval/promotion/reuse cut attack success 38.2%→0.9% on LongMemEval. [Misattribution Gap](https://arxiv.org/html/2605.22842), a document in a shared vector store re-emerges as trusted context with provenance lost, cited as authority in 59 of 65 valid entries. [Memory-hopping](https://arxiv.org/html/2609.35576v1), attacks spread via shared artifacts to 60–80% of agents over up to eight hops. [SuperLocalMemory](https://arxiv.org/html/2603.02240v1), per-memory provenance and trust scores; OWASP lists this as ASI06.
- `[first-hand]` Parallel subagents had isolated contexts and returned only self-reported summaries the parent had to verify. No structured shared state existed beyond the filesystem and terminal env; an exported `DATABASE_URL` leaked between parallel agents and broke isolation (the [Hermes docs promise isolated context](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation), but env isolation is not what we saw). Results arrived only when the whole batch finished. Nothing recorded which agent decided what or why in a form a later agent could query. This matches the documented summary-only return and [audit trail lost on compression](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban).

## 4. Gaps a graph-native coordination layer could fill

All bullets are `[inf]`, mapped to FalkorDB as briefed (property graph, Cypher, per-tenant graphs, parallel snapshot reads, per-graph serialized and per-query atomic writes). I did not re-verify engine properties here; check before claiming them in the demo.

1. **Tasks, claims, leases and handoffs as edges.** Today these are rows ([Kanban](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban)) or file locks ([teams](https://code.claude.com/docs/en/agent-teams)). One Cypher query that matches an unclaimed task and creates `CLAIMED_BY` is atomic; `HANDED_OFF_TO` edges can carry artifacts.
2. **Queryable decision provenance across sessions.** `(:Agent)-[:DECIDED]->(:Decision)-[:BASED_ON]->(:Fact)` and `SUPERSEDES`. Fixes summary-only returns ([Claude Code](https://code.claude.com/docs/en/agent-teams)) and audit trails lost on compression ([Hermes](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban)).
3. **Structural conflict detection between agents' facts.** CrewAI leaves it to an [LLM](https://docs.crewai.com/en/concepts/memory.md); the [position paper](https://arxiv.org/html/2603.10062) says no detector exists. `CONTRADICTS` edges and same-subject/different-value queries flag conflicts, with a model only adjudicating.
4. **Per-tenant and per-run isolation.** One graph per tenant or run, so a leaked env var cannot cross-write. A2A's [`tenant`](https://a2a-protocol.org/latest/topics/multi-tenancy/) and Kanban's tenant are labels inside one store; graph-level separation is stronger.
5. **"What did agent X know at step N?"** LangGraph [time-travels within a thread](https://docs.langchain.com/oss/python/langgraph/checkpointers). Bitemporal `valid_from/valid_to` plus `OBSERVED_BY` edges answer it across agents.
6. **Taint-aware promotion from private to shared memory.** [MAPLE-Guard](https://arxiv.org/html/2608.00426v1) gates promotion. `DERIVED_FROM` edges plus a `trust` property let one traversal quarantine every descendant of a bad source, the provenance the [Misattribution Gap](https://arxiv.org/html/2605.22842) paper says gets lost.
7. **Shared state without locks.** ADK says use [locks or an external DB](https://google.github.io/adk-docs/agents/workflow-agents/parallel-agents/). Parallel snapshot reads let many agents query while a single writer commits (the Track 02 concurrency pitch).
8. **Partial results as they land.** Batches return together `[first-hand]` and Anthropic's lead [waits synchronously](https://www.anthropic.com/engineering/multi-agent-research-system). Agents writing findings to the graph let the parent poll mid-run.
9. **Ownership/overlap checks before work starts.** Teams rely on [advice to own different files](https://code.claude.com/docs/en/agent-teams). `OWNS` edges plus a pre-write overlap query address Cognition's [conflicting implicit decisions](https://cognition.com/blog/multi-agents-working).
10. **Episodic, semantic and procedural memory in one linked store.** Frameworks split them across checkpoints, Stores and vector DBs ([LangGraph](https://docs.langchain.com/oss/python/langgraph/persistence), [ADK](https://google.github.io/adk-docs/sessions/)). Edges from episode to produced facts to the procedure used keep them traceable.
11. **MCP as front door.** MCP is [stateless](https://modelcontextprotocol.io/docs/learn/architecture) with no claim or provenance primitive. A graph MCP server exposing `claim_task`, `record_decision`, `query_provenance` supplies them to any MCP-capable framework.
12. **Dead-agent recovery across hosts.** Teammate status can [lag and block dependents](https://code.claude.com/docs/en/agent-teams#limitations); Kanban reclaims stale work but is [single-host](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban). Lease-expiry timestamps on claim edges let any agent reclaim.

**Caveats.** Per-graph write serialization makes writes the hot path: batch into single queries, and use MULTI/EXEC where multi-query atomicity is needed. A graph makes semantic conflict detectable and auditable; it does not resolve it.

**Demo idea:** replay the leak and summary-only failure `[first-hand]`, then run two agents on a shared graph with claim edges, a decision log and a contradiction query, ending with one Cypher answer to "what did X know at step N, and who decided Y?"
